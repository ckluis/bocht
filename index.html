01 — The framework

One process. No sidecars.

Bocht is a backend framework written as one Bend program. Bend compiles it to C, clang compiles that to a single native binary, and that binary is the whole service: no database process, no reverse proxy, no queue. Everything a request touches lives in the same address space.

Inside the binary · request path1.97 MB · arm64 · builds in ~25 s
Socket
HTTP/1.1 with keep-alive — 100 requests per connection, 64 KB body cap, clean 400/411/413/431 on malformed input.
Auth
Bearer keys scoped to a tenant and a role (admin or member), with rotate and revoke endpoints. No token, no parsing: a 401 comes back before the body is read as JSON.
Limits
Per-credential rate limits, plus separate budgets for key management and admin restarts. Bursts get a 429, not a crash.
Router
20 routes: keys, users, articles, claps, publications, members and an event feed over REST — and POST /mcp for the CMS.
Store
Segmented write-ahead log (64 MiB segments, fsync'd) plus snapshots whose trailer binds the record count and an HMAC. A forged or truncated snapshot is refused at boot.

Honest limits

  • Single node. No replication, sharding or consensus.
  • The log survives the process dying, not the power going out.
  • One request at a time. A slow request blocks every client — which is why the curve in bochtCMS mattered.
  • Bend moves fast: the builder reports breaking changes in every release from 2.0.18 to 2.0.34, and the pinned r61 release doesn't build on 2.0.34 (confirmed).
02 — The method

Built by one AI. Checked by another.

I didn't write Bocht. I directed an AI app builder that wrote it, and it worked under a verification discipline worth stealing: no claim ships unless it can be re-derived from files on disk.

1 · Probe

Every capability has a script

Each one ends with one canonical line: RESULT: PASS=n FAIL=0. No line, no claim.

2 · Manifest

Results bound to a binary

A stamp script writes the exact binary's SHA-256 next to every result file it produced.

3 · Verify

A second script audits the ledger

Source hash, binary hash, build exit code and manifest must all agree before "done" is written.

4 · Canary

The pinned build is watched

A read-only backup and a hash sidecar are checked hourly against the live binary.

5 · Ledger rule

Never say "flawless"

Verified claims only. Never production-ready, clustered, replicated or bug-free.

What the discipline got right

  • Every hash in the bundle matched its README.
  • The 43-test suite reproduced on a different OS and CPU.
  • By the builder's account, its own first run caught a real protocol bug: the tool name read from the wrong object.
  • Writes survived kill -9: 303 of 303 acknowledged writes, and 20 of 20 single-write cycles.

What it can't see

  • A manifest proves which binary produced a log. It doesn't prove the log tested the right things.
  • All 43 checks used tiny payloads. Nothing timed a realistic post.
  • The suite passed on every version — including the one where a read deleted a post.
  • The shipped verifier needed a ledger file that wasn't in the bundle, so it couldn't be run.
03 — Still open

What the audit didn't close.

The evaluation fixed the CMS and proved it. The framework release underneath, r61, is pinned and was left as shipped, so these stand.

Same bug, other door

The quadratic JSON id parse fixed in bochtCMS likely also sits in r61's REST clap path (jf_raw_go in src/med_parse.bend). Unfixed and unmeasured here.

Pinned to an old compiler

r61 was built on an earlier Bend 2.0 release and does not build on 2.0.34 (confirmed). Its own README says both that it does and that it doesn't.

One node, one request

No replication, sharding or consensus, and requests run one at a time, so any slow request stalls every client.

Proof-ready, proof-free

Bend can check proofs about programs. Bocht writes none; its guarantees come from tests and manifests, not types.

The full audit, including the curve, the builder's regressions and the one-function fix, is on the bochtCMS page.

The Bend series

One language. Three builds. One auditor.

Three programs, one young language, one method. Each was written by an AI app builder in Bend 2 under an evidence-first discipline, then handed to Claude Code to check: reproduce every claim, attack it, profile it, fix only what is proven, and show the fix changed nothing else. Every time, the builder's own tests passed, and something real was still wrong.
